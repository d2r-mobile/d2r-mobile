# 大秘境随从生命：回归清单

[English](qa-rift-pet-life.md) | **简体中文**


本清单的验证矩阵由 [#23](https://github.com/jhaizhou-ops/d2r-mobile/issues/23) 的报告人提出，这里按修正后的行为逐条核对、改写成回归清单。标「已验」的是维护者实际跑过并读到数的；标「未验」的还没有人跑过，欢迎补。

## 根因与修正（已合入）

- 读生命上限用的原版取属性函数，在随从这类单位上给的是**合计**（基础项 + 技能 / 光环的加成，百分比加成已乘进去）；写用的设属性函数写的是**基础项**。原先的代码读合计、乘上秘境倍率、写回基础项。
- 随从带「生命上限 +N%」（数据表里只有战斗体制 Battle Orders 和橡木智者光环 Oak Sage 会给随从这条属性）时，游戏在我们写的值上再乘一遍 (1 + N%)；下一轮读回的值不等于上次写入，又被当成新基数。每 10 拍涨 (1 + N%) 倍。
- 涨到属性上限（8388607 点）后，合计溢出成负数，取属性函数按最小值返回 1 点——这就是日志里「封顶后回到 1」。那一刻随从实际只剩几点生命。
- 修正：基数、比较、侧文件一律按基础项；加成由游戏自己乘。封顶按「合计不超过属性上限」留余量。放弃当拍就设回基数（同结算）。束缚恶魔的基数若高过原版封顶公式的现算值（修正前留在存档里的），读档时设回封顶。

## 怎么读数

- `DM_RIFT_TEST_PETDUMP=1`：每 125 拍一行 `秘境：随从读数 …[类型 T 类号 C id I 等级 L 生命上限 合计（基础 基础项）当前 当前生命]`。
- 每次调整一行：`秘境：随从 id I（宠物类型 T，类号 C）生命上限基础项 a → b（基数 x，第 N 层 ×m）；合计 c → d`。**正常情况下进层 1 行、离开（结算 / 放弃）1 行，中间没有。**
- 一次性修正触发时一行：`秘境：<角色> 的束缚恶魔（类号 C）生命基础 X 超过上限，已设回 Y`。
- 造现场的测试开关：`DM_RIFT_TEST_PETPCT=<百分数>`（给每只随从加生命上限 +N%）、`DM_RIFT_TEST_START=<拍>:<层>`（直接开某层）、`DM_RIFT_TEST_ABANDON=<拍>`、`DM_RIFT_TEST_SAVE=<拍>`（到拍请游戏存盘）。
- 期望值手算：放大后基础项 = 基数 × 本层倍率；合计 = 基础项 × (1 + N%)。例：基数 27000、第 77 层 ×3.891、+77% → 基础项 105057、合计 185950。

## 没有采纳的部分

报告人随清单提交的诊断补丁（每次调整记一条详细记录并限流）没有合入：修正后正常一场只有一两次调整，那套按「合计」口径设计的记录不再有区分力。上面「怎么读数」里的随从读数行已带上合计、基础项、当前生命三个数，够用来核这张表。
