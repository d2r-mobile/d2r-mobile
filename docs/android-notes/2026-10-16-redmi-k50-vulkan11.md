# Redmi K50 Ultra on Vulkan 1.1: first GPU output (2026-10-16)

中文：[2026-10-16-redmi-k50-vulkan11.zh-CN.md](2026-10-16-redmi-k50-vulkan11.zh-CN.md)

Times are NZDT (UTC+13). Fixes are on branch experimental build (from `main` `recorded build`), tested merged into experimental build (`recorded build`, which also carries the changes). This is a bring-up record, not playability acceptance.

## Device and inputs

- **Device:** Redmi K50 Ultra (`22081212G`), HyperOS 3 / Android 15 (API 35), Adreno (TM) 730, Vulkan **1.1.128**, driver `0x8026705f` (512.615). No `VK_KHR_format_feature_flags2`.
  - `verify_xgs.py`: PASS, 6,931 files, 617,755,664 bytes.
  - On-device `sha256sum -c`: all 6,931 OK.
  - Runtime root: internal `files/dm/`.
- **Deploy note:** `deploy_xgs.py --apply` streams a tar into `adb exec-in`. From WSL through Windows `adb.exe` that killed the adb server after about 43 MB, twice. A wrapper with the script's own `verify()`, device hash check, running-app checks and `activation_script()`, transferring by `adb push` of the tar instead, activated the library in 18 s.
- **Other inputs:** game data is upstream's trimmed pack, `main`/`sdk` are r44 `DM_TARGET=android` touch modules, and the host tables come from the same RomFS (see [2026-10-16-linux-build.md](2026-10-16-linux-build.md)).

- **Features:**

  - Absent: `shaderFloat64`, `shaderInt64`.
- **Subgroups:** size 64. Stages `0x30` (fragment and compute only, no vertex). Operations `0xbf` (all but clustered).
- **Limits:** UBO range 64 KiB, 32 dynamic UBOs, 16 dynamic SSBOs, 64-byte UBO/SSBO/texel alignment, 7 bound sets, 8 color attachments, 32 KiB shared memory, 1 viewport.

## Failures and fixes

| # | First failure (with the 6,931 library) | Cause | Fix (commit) |
|---|---|---|---|
| 1 | `Image format lacks formatless-write support` | The storage-image check chained `VkFormatProperties3`, which needs Vulkan 1.3 or `VK_KHR_format_feature_flags2`; on 1.1 its flags stay zero | Without the extension, apply the spec's "Formats Without Shader Storage Format" rule: feature + listed format + `STORAGE_IMAGE_BIT`. Devices with flags2 are unchanged (`recorded build`) |
| — | — | — | Read-only capability report at initialization; the linear-filter fatal prints compare mode, feature bits and texture (`recorded build`) |
| 2 | `NVN sampler linear filtering unsupported min=5 mag=1 compare=1/5 format=0x32 vk=124` | Shadow maps are D16, sampled with linear depth comparison; this driver cannot linearly filter D16 | Where D16 lacks linear filtering and `X8_D24` has sampling, linear filtering, depth attachment and transfers, store NVN DEPTH16 as `X8_D24`. Uploads/readbacks convert 16↔24-bit exactly (all 65,536 values round-trip). Constant depth bias is ×256 for those attachments. Devices that filter D16 are unchanged (`recorded build`) |

## Result

APK `0.1.7-dev` / code 8, SHA-256 `5a0e4cc8e041e5e7013ee10dffcae339448e5d11868a1f77b89a4ec3ff8eaedb`, overlay-installed with the same key.
- **First GPU output on this device:** the "Select Hero Class" screen renders, with all classes, campfire lighting, character shadows and touch controls. No FATAL and no `【红】` lines in about 45 s. 106 shaders loaded.
- **`NVN PERF v=1` (60-frame windows):**
  - Front-end screens: 46.6–60.3 fps, GPU 4.5–5.1 ms, CPU submit 10–14 ms.
  - Hero select (about 1,490 draws, 60 passes per frame): 7.01 and 7.58 fps, GPU 71.4 and 73.6 ms, CPU submit 131 and 119 ms. GPU time and fence waits overlap, so don't add them.
  - The vivo X200 Ultra (code 10, camp) is 12–13 fps with GPU about 37 ms. That's a different scene, not a comparison.

## Not verified

- **Depth conversions:** no D16 depth upload or readback happened in this run (0/0), so those conversions have not run on a device yet.
- **Depth bias:** shadows looked normal at hero select only. Shadow acne or peter-panning has not been checked in the world.
- **The rest of the acceptance list:** character creation, entering the world, movement, NPCs, inventory/skills, sound, background/resume, save/reload, outdoor combat.
- **vivo / Vulkan 1.3 regression of these changes:** not run (no device). By construction the 1.3 paths are unchanged:
  - the storage check takes the old path when flags2 is present;
  - D16 stays D16 when it can be linearly filtered (vivo already sampled it linearly without a fatal).
- **Manifest and README:** they still declare Vulkan 1.3. Part D of the handoff waits until the 1.1 path is accepted.
