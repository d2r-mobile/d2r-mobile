# Redmi K50 Ultra 跑 Vulkan 1.1：首次 GPU 出图（2026-10-16）

English: [2026-10-16-redmi-k50-vulkan11.md](2026-10-16-redmi-k50-vulkan11.md)

时间为新西兰夏令时（UTC+13）。修复在分支 试验构建（基于 `main` `记录版本`），并入 试验构建（`记录版本`，同时含 改动）后测试。这是上机记录，不是可玩性验收。

## 设备与来料

- **设备：** Redmi K50 Ultra（`22081212G`），HyperOS 3 / Android 15（API 35），Adreno (TM) 730，Vulkan **1.1.128**，驱动 `0x8026705f`（512.615）。没有 `VK_KHR_format_feature_flags2`。
  - `verify_xgs.py`：PASS，6,931 个文件，617,755,664 字节。
  - 设备端 `sha256sum -c`：6,931 个全部 OK。
  - 运行根目录：内部 `files/dm/`。
- **部署说明：** `deploy_xgs.py --apply` 把 tar 流式送进 `adb exec-in`。从 WSL 经 Windows `adb.exe` 这样做，两次都在约 43 MB 处把 adb 服务弄掉了。改用包装脚本：沿用脚本自身的 `verify()`、设备端哈希核对、运行中检查和 `activation_script()`，只把传输换成 `adb push` 整个 tar，18 秒完成激活。
- **其他来料：** 游戏数据是上游剔零包，`main`/`sdk` 是 r44 `DM_TARGET=android` 触屏模块，宿主表由同一份 RomFS 生成（见 [2026-10-16-linux-build.zh-CN.md](2026-10-16-linux-build.zh-CN.md)）。

## 能力报告（新增 `capability_report()` 在启动时打印）

- **特性：**
  - 有：`drawParameters`、`shaderStorageImage{Read,Write}WithoutFormat`、`shaderStorageImageExtendedFormats`、`shaderImageGatherExtended`、细分、几何、`occlusionQueryPrecise`、`depthBounds`、`depthClamp`、`fillModeNonSolid`、BC、ASTC LDR、ETC2、各向异性、`logicOp`、`dualSrcBlend`、`independentBlend`、裁剪 / 剔除距离、`shaderInt16`。
  - 没有：`shaderFloat64`、`shaderInt64`。
- **子组：** 大小 64。阶段 `0x30`（只有片元和计算，没有顶点）。操作 `0xbf`（除 clustered 外都有）。
- **限制：** UBO 范围 64 KiB，动态 UBO 32 个、动态 SSBO 16 个，UBO / SSBO / texel 对齐均 64 字节，可绑定 7 个 set，8 个颜色附件，共享内存 32 KiB，1 个视口。
- **深度格式**（optimal tiling 特性位；`0x1000` = `SAMPLED_IMAGE_FILTER_LINEAR`）：

  | 格式 | 特性位 | 线性过滤 |
  |---|---|---|
  | `D16_UNORM` | `0x1e601` | 不支持 |
  | `D32_SFLOAT` | `0x1e601` | 不支持 |
  | `X8_D24_UNORM_PACK32` | `0x1f601` | 支持 |
  | `D24_UNORM_S8_UINT` | `0x1f601` | 支持 |

## 失败与修复

| # | 首个失败（用 6,931 库） | 原因 | 修复（提交） |
|---|---|---|---|
| 1 | `Image format lacks formatless-write support` | 存储图像检查无条件链入 `VkFormatProperties3`，它要 Vulkan 1.3 或 `VK_KHR_format_feature_flags2`；1.1 设备上这些位保持为零 | 没有该扩展时按规范「Formats Without Shader Storage Format」：特性 + 列表内格式 + `STORAGE_IMAGE_BIT`。有 flags2 的设备不变（`记录版本`） |
| — | — | — | 初始化时打印只读能力报告；线性过滤的致命错误附带比较模式、特性位和贴图（`记录版本`） |
| 2 | `NVN sampler linear filtering unsupported min=5 mag=1 compare=1/5 format=0x32 vk=124` | 阴影贴图是 D16，用线性深度比较采样；这台驱动不能线性过滤 D16 | D16 不能线性过滤、而 `X8_D24` 支持采样、线性过滤、深度附件和传输时，把 NVN DEPTH16 存成 `X8_D24`。上传 / 回读做 16↔24 位精确换算（65,536 个值全部往返一致）。这类附件的常量深度偏移 ×256。能过滤 D16 的设备不变（`记录版本`） |

## 结果

APK `0.1.7-dev` / code 8，SHA-256 `5a0e4cc8e041e5e7013ee10dffcae339448e5d11868a1f77b89a4ec3ff8eaedb`，同签名覆盖安装。
- **这台设备首次 GPU 出图：** 「选择英雄职业」界面正常显示，各职业角色、篝火光照、角色阴影和触屏控件齐全。约 45 秒内没有 FATAL，也没有 `【红】` 行。加载了 106 个着色器。
- **`NVN PERF v=1`（每 60 帧一个窗口）：**
  - 前端界面：46.6–60.3 FPS，GPU 4.5–5.1 ms，CPU 提交 10–14 ms。
  - 选职业场景（每帧约 1,490 次绘制、60 个 pass）：7.01 和 7.58 FPS，GPU 71.4 和 73.6 ms，CPU 提交 131 和 119 ms。GPU 时间和 fence 等待有重叠，不能相加。
  - vivo X200 Ultra（code 10，营地）为 12–13 FPS、GPU 约 37 ms。场景不同，不能直接比较。

## 未验证

- **深度换算：** 本次运行没有发生 D16 深度上传或回读（0/0），这两条换算还没在设备上跑过。
- **深度偏移：** 只在选职业界面看到阴影正常，还没在野外检查阴影粉刺或悬浮。
- **验收清单其余项：** 建角、进局、移动、NPC、背包 / 技能、声音、后台 / 恢复、存档 / 读档、野外战斗。
- **这些改动在 vivo / Vulkan 1.3 上的回归：** 没跑（没有设备）。按构造 1.3 路径不变：
  - 有 flags2 时存储检查走原路径；
  - D16 能线性过滤时仍存为 D16（vivo 此前线性采样 D16 并未报致命错误）。
- **清单与 README：** 仍声明 Vulkan 1.3。按交接 D 部分，等 1.1 路径验收后再改。
