# Ideas from #112 measured on this port (2026-10-21)

[中文](2026-10-21-ideas-from-112.zh-CN.md)

#112 (the project's `android-integration`) is a separate Android port with its own Vulkan backend. Its changes cannot be cherry-picked here, so each idea that sounded like an improvement for this port was rebuilt behind a switch and measured on the phone. One was kept: the 3D brightening (`recorded build`).

## How it was measured

- Redmi K50 Ultra (Snapdragon 8+ Gen 1, Adreno 730).
- A test build of `recorded build` plus switches for each idea. The switches were not committed.
- In-process A/B: `files/dm/gfx-ab-toggle` = 10 flips the idea on and off every 10 s in the same run, so both halves share the phone's temperature.
- Each run is a cold start, Play, and 180 s in the camp, starting at 29.4–34.5 °C.
- Adjacent on/off phases give paired differences, shown below with a 95% confidence interval.
- GPU items ran at a fixed 3D scale of 0.85 (`DM_3D_SCALE=0.85`, `DM_3D_SCALE_DYN=0`); the others ran at production defaults.

## Results

| Idea (#112 commit) | What was measured here | On − off | Kept |
|---|---|---|---|
| Cache in front of the dirty tracker's range lookup (`f09e07f`) | Submit CPU; about 1,350 lookups a frame | CPU −0.22 ± 0.25 ms (21 pairs). Without the cache a lookup scans only ~5 slots | no |
| No occlusion queries in depth-only passes (`a4b8959`) | GPU at 0.85 | GPU +0.002 ± 0.056 ms (20 pairs) | no |
| Attachment load/store reductions (`7b1b963`, `9cff679`, `ce0e887`): upper bound | Every pass begins with a twin whose ops are DONT_CARE. This breaks the picture and only bounds the possible gain | Color loads: GPU −0.06 ± 0.10 ms. Depth/stencil stores: +0.003 ± 0.009 ms. All four: +0.19 ± 0.04 ms (slower) | no |
| Yield backoff for the guest main thread (`e735628`) | Per-frame TSV (frame time, main-thread yields) plus the perf windows | Yields 105 → 16 a frame. Frame and CPU time unchanged; frames over 18 ms +0.9 ± 0.9 points | no |
| 3D brightening, as on iOS (`fe7b655`) | Den of Evil screenshots, then an A/B of the cost | Exposure 4.00 in the Den; the cave is clearly lit where it was nearly black. GPU −0.11 ± 0.15 ms, CPU −0.27 ± 0.39 ms (17 pairs) | yes, `recorded build` |

The load/store line is #112's largest recent optimization; there it reduced the bandwidth estimated from attachment sizes. On this engine and driver even the bound saves nothing, so the per-pass coverage table it needs was not built.

## Checked and not needed here

- The level table for the cave brightening (`3c26392`): this build generates the real `dm_bright_levels.inc` from the player's files, not an empty placeholder.
- Batched `mprotect` on writebacks (`6f4235c`): in the camp the host never unprotects pages before writing ("宿主写前解保护 0 页"); the page faults are single pages by nature.
- Multi-layer texture uploads in one copy (`0f107b3`): this engine already uploads all layers and levels of an image with one copy.
- Tap auto-targeting (`1ce1e64`): this port runs the shared host's `hle_target.c` and installs it at start (`自动选怪：Boss > 精英 > 普通（观测门 7）` in the log).
- The wider «Русский» cell (`acfbf84`): the wider box touches the Español checkbox, and in the English UI the row's label «Language» also wraps. Both come from the shared layout in `touch_layout.py`, so the fix belongs there, for both platforms.

## Next lead: the first camp frame

The ground-material bake (compute shader `0f715b1a5e03f11f`, 196 dispatches, 58.6 ms of the ~100 ms entry hitch) compiles on the Adreno 730 to:

- 2,735 instructions (1,094 32-bit ALU)
- register footprint 16
- no scratch
- max active invocations 1 (driver statistics, marker `gfx-pipe-stats` with `gfx-no-warm`)

So it is not spilling. Most likely its 35 texture reads per invocation are poorly hidden at that occupancy.
