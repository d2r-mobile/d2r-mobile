# D2R Mobile — Android

English: [README.md](README.md)

基于 [the project-ops/d2r-mobile](https://github.com/the project-ops/d2r-mobile) 的实验性 Android 移植，将离线**《暗黑破坏神 II：狱火重生》**及其游戏专用触屏界面带到 Android ARM64。目前的测试设备是**小米 15 Ultra / 骁龙 8 Elite / Adreno 830**。

**开发版已经在目标手机上实际运行游戏。** 启动、角色选择、进入营地和正常存盘退出已经测试；用户也已验证战斗、技能、拾取、背包拖动和储物箱拖动。完整设备兼容性、完整 iOS 触屏等价和持续稳定 60 帧仍在推进。

> **`main` 是本 fork 唯一的正式 Android 开发基线。** 原 Android 集成通过 PR 归入主线。后续改动使用短期功能分支；原项目通过 `upstream/main` 跟踪，适用更新经审查后并入我们的 `main`。

**显示以 Turnip 为基线。** 系统高通驱动保留为兜底，但此前发黑及光照缺陷未被实验性 UBO workaround 修复，目前不优先推进该驱动专项。

Android 技能按钮采用与上游 iOS 一致的透明银白轮廓处理，常态和按压图像仅转换一次并缓存。测试手机已验证箭头、拳头图标、按压状态与空技能槽；其他职业技能仍需逐一验证。

Android 音频可在后续启动／恢复时重新打开失败或断开的 AAudio 流，同时保留单一消费者的静音回退。生产代码失败回归已通过；来电／焦点、耳机／蓝牙切换及实际出声恢复仍需实机验证（）。未证明应用始终在前台时能立即从路由切换恢复。

帧数会随场景和运行时间变化。部分营地采样接近 60 帧，不代表战斗或长时间游玩能稳定 60 帧；节能效果尚未得到证明。上游 iOS 的性能成果属于 Apple 构建，不能直接作为 Android 结论。

性能浮层优先显示近两秒的实际上屏 FPS，以及上屏间隔的 P95／最慢值；驱动未提供该数据时明确标为提交 FPS。均匀的 60／30 帧，间隔应接近 16.7／33.3 ms，只有平均帧率不能证明流畅。帧率上限提供不限、60、30；限帧无法让已经超出时间预算的慢帧变快。两档限帧都按刷新周期对齐上屏时刻（`debug.d2r.display_pacing=0` 可关闭），减少 120 Hz 屏上迟到帧之后的 8.3 ms 补拍间隔。

启动页的“调试采集”默认关闭，下次启动游戏生效。“显示帧率”独立控制，关闭采集时仅显示 FPS 和上屏间隔。详细计时、电池／内存取样、慢帧文件、可选抓帧和输入追踪均受采集开关控制；致命错误记录与游戏同步仍保留。开启采集后，异常帧日志按帧率上限调整阈值，通常最多每秒采样一次；逐绘制计时仍需额外启用高级诊断标志。关闭诊断不代表已实现稳定60帧。

已接受的 CPU 改进包括描述符编码与哈希合并遍历、相同计算绑定复用，以及采样器与贴图共用一次加锁查询，已通过本地检查和短时营地站定测试。本次顺序采样中，叠加60帧候选平均56.2FPS，基线两轮54.2／50.6FPS，但P95仍为25ms且温度、顺序不同，尚未证明稳定60帧或可重复的省电收益；30帧候选平均30.0FPS，P95为33.3ms。

启动页全屏“中／低”分别对应内部3D640／480高，界面与输出保持720高。输出1600×720时，中档的理论3D像素量约为1280×720的99%；像素量接近不保证帧时间完全相同。

ADPF 已接入翻译线程的完整帧周期及实际限帧预算，接口不可用时正常回退，切至不限帧时关闭旧限帧会话。Vulkan 保留三个槽／256 draw 的保守默认和 32 MiB 临时内存上限。短时营地六槽对照减少了 ring 等待，但尚未证明 FPS 提升；八槽和更大切批阈值仍待对照，不代表已实现稳定 60 帧或节能。

已合入的 CPU 改进包括线程上下文缓存碰撞修复、小块客体读取优先使用现有堆权限租约并保留安全读取回退，以及连续宿主写入页的批量解保护。后者保持精确页范围和逐页代数；此前六分钟营地运行中，保护调用从约 300 降至 28–36 次／帧，累计保护耗时从 1.25–1.35 降至 0.42–0.50 ms／帧。这证明工作量减少，不代表已证明提帧或省电。用户也已确认进出营地持续移动中断及技能图标短暂问号不再出现。锁自旋仍保持关闭。附件清屏折叠与图像用途收窄（#331）经用户开启实机测试、未观察到问题后默认启用；重启前设置 `debug.d2r.attachment_clear=0` 或 `debug.d2r.narrow_image=0` 可分别关闭。尚未证明提帧或节能收益。

诊断读数有范围限制：CPU 时间覆盖 NVN 命令翻译，GPU 时间覆盖已测量的命令批次，快照 MiB／帧统计客体内存快照读取。它们分别不是完整帧的 CPU 时间、完整 GPU 时间或 GPU 总带宽。功率估算来自电池电流和电压，充电时不能据此认定游戏或整机耗电。对照应保持场景、温度和充电条件一致并重复采样。

## 体验开发版

使用从集成分支构建的工程 APK。目前属于已在指定设备测试的开发移植，并非通用兼容或稳定发行版承诺。

1. 安装 APK 并打开启动页。需要保留已有数据时，使用相同包名及签名的兼容更新。
2. 点“导入数据包”，选择本地准备的 Android 游戏数据 ZIP，等待显示已安装／就绪。
3. 在已支持的高通测试手机上选择**内置 Turnip**。也可以导入自定义驱动 ZIP；不兼容驱动会在游戏启动前被拒绝。导入的驱动可在启动页删除。目前只有一个自定义驱动槽，成功导入新包会替换旧包。
4. 先使用“**全屏 · 720 高度**”档。选项直接显示实际输出尺寸（20:9 手机为 1600×720），另有保持界面／输出 720 高、仅内部 3D 渲染 480 或 640 高的低负载档、900 高全屏档及 1280×720、1600×900 的 16:9 档，不再与掌机／主机选项叠加缩放。480 档已在测试手机确认画面生效，通过降低 3D 清晰度减少渲染像素，可重复的省电收益仍待验证。沉浸式启动页左侧为启动与存档导入／导出，宽屏下右侧滚动容纳设置及游戏包管理。
5. 启动游戏。结束后通过游戏存盘退出及应用正常退出流程关闭。

**导入 ZIP 是什么意思？** 启动页会解压、校验并将内容写入应用自己的数据目录：资源位于应用专属存储，游戏模块和存档位于内部应用存储。ZIP 只是导入源，游戏不会每次启动都读取它。确认成功导入并能启动后，可以删除“下载”目录里的那份 ZIP；如果以后可能重装，建议另留备份。清除应用数据或卸载可能移除已导入数据和存档，请先导出存档。游戏数据不会被写入已经安装的 APK 内。

此导入流程需要已准备好的 Android 数据包，任意 Switch 原始游戏包不能直接当作就绪的 Android 数据包导入。请使用自己合法拥有的 Switch **1.0.34.0，包含「术士君临」资料片**的文件（仓库数据版本 **3.3.94012**）。[游戏文件准备](../GAME_FILES.zh-CN.md)说明源文件与版本要求，其中 Apple 部署步骤与 Android 启动页不同。本仓库不提供游戏、密钥或存档。

## 已知限制与优先级

- 用户已确认进出营地时持续移动不中断，技能按钮短暂闪问号也已消失；更广泛的区域／设备覆盖仍见 。
- 完整 iOS 触屏呈现仍在适配。Android 已接入现有高价值掉落震动队列，遵循系统触觉设置，并在恢复前丢弃后台积压事件；真实掉落震感仍待实机验收。地图目标／秘境 HUD 资源、商店图标显示及完整交互／设备矩阵仍有未验收项；攻击和拖动可用不代表整套触控已完成。
- 当前优先优化持续性能：分析 CPU 翻译路径，按实测热点改进，并保留 GPU 同步、资源所有权和验证。ADPF 帧接线已合入，但接口调用成功尚未证明可重复的帧率或省电收益。
- Android 的 CPU-only 页在有界 64 KiB 窗口内合并已保护页的缺页处理，GPU 写过的页保持精确并截断合并。着色器查找复用现有字节键哈希表；客体互斥锁的有界自旋可用于测量（`debug.d2r.lock_spin=20` 在下次启动启用 20 微秒），但本机对照尚未证明可重复收益，因此默认关闭。关闭调试采集也会停掉脏页保护和主线程让出的计时。持续战斗和省电收益仍需单独测量。
- 文本输入框已监听输入法组合标记，并在提交前重新校验。存档导入拒绝截断包及条目大小／CRC 不符；中断替换会在启动／导出前恢复，恢复失败则阻止启动。宿主回归已通过；真实输入法、实机导入中断、后台恢复、手柄、音频及完整通关仍需更广泛验收。清理时归档的历史诊断／契约任务，不因真实游戏首跑就被视为已证明。

## 开发

```sh
git clone --branch main https://github.com/d2r-mobile/d2r-mobile.git
cd d2r-mobile

# 无需游戏的宿主测试及 Android ARM64 交叉编译。
export DM_ROOT=/path/to/external-disk/d2r-work
./dm/android/test.sh -DDM_ANDROID_VULKAN=OFF
./dm/android/build.sh -DDM_ANDROID_VULKAN=OFF

# 查看独立的可玩 APK 构建入口及选项。
python3 dm/android/tools/build.py --help
```

无需游戏的工具使用 CMake 3.22+、C 编译器和 Capstone 5；原生 ARM64 用例需要 ARM64 宿主。Android 交叉编译需要 NDK，当前构建使用 r29。首次配置可能下载固定版本依赖。宿主测试通过合成 Vulkan 驱动检查生产管线缓存的损坏拒绝、驱动隔离、保存失败保留旧文件及退出刷盘；这不代替实机验证。工具设置与历史样例见 [Android 开发说明](../../dm/android/README.zh-CN.md)。

可玩 APK 的入口是 `dm/android/tools/build.py` 的 `--game-run` 模式，需要对应参考工具链、SDK／build tools、JDK、着色器工具和本地准备的资源；按实际构建提供 `--turnip`、`--touch-art` 输入。每次构建重建可丢弃的 `assets`、`res`、`java-classes`、`dex` 打包目录，源输入请放在这些目录之外；依赖缓存保留。`--no-turnip` 也排除缓存中的驱动库，`--install` 使用清单中声明的包名。通用 APK 可在手机导入游戏模块。不要发布嵌入游戏代码或游戏派生美术的构建。`dm/android/app/build.sh` 构建的是较早的合成诊断 APK；`setup.sh` 是上游 Apple 准备流程。

参与开发请从  确定边界明确的任务，以 topic PR 提交到 `main`，报告准确源码提交、测试与实际设备条件。明确拒绝不支持的路径，保留扫描、W^X、所有权和失败检查，并区分实现与实机验收。游戏内容、凭据、存档及原始设备日志不进入 GitHub。另见 [CONTRIBUTING.zh-CN.md](../../CONTRIBUTING.zh-CN.md)。

每项任务收尾时，由协调者核对精确 PR head 和必要证据，仅关闭验收范围已满足的 issue，仅合并通过验收的修改。确认工作已保留、且没有活跃工作区或 worker 需要分支后，再删除任务分支；待测候选和未完成 PR 继续保留。行为、限制或已验证进度变化时同步更新中英文 README，并区分已合并源码与本地实机候选。
