# 画面闸门

English: [screenshot_gate.md](screenshot_gate.md)

画面闸门把**宿主**（`dm/host` 的 `dmhost`，在 Mac 上执行改写后的游戏程序）画出的关键画面，与**真值**（用打了补丁的 Ryujinx 模拟器跑原版游戏截下的参照图）逐页比较，判断有没有整块缺失、缺光照或结构走样。

为什么要对真值比：只拿宿主的新图比宿主的旧图，两边都黑也会报「一致」。

两边的显卡与着色器链都不同，所以不要求逐像素相同，用下面几条判据。

## 一条命令

```
dm/verify/shotgate.sh [产物目录] [页名…]
```

- 产物目录缺省是当前代号的 `keypage` 产物（`dm/tools/product.sh path keypage`）；页名缺省是 `shotgate_pages/` 下全部。
- 开跑先 `make` 宿主。每页起一个宿主（`hostshot.sh`），用标准存档的新副本开局，按页规格里的键序走到那个画面，到触发点截图，再由 `shotgate.py` 与真值参照图比。各页互相独立，并行跑。
- 每页打一行 `SHOTGATE <页> OK|RED …`，末行 `SHOTGATE_ALL OK|RED → <报告路径>`；退出码 0 = 全绿。

报告与现场：

- 有红时，整份现场留在 `$DM_ROOT/run/verify/dm/shotgate/<时刻>_<工作树名>_<进程号>…/`：`index.html` 是汇总，每页一份 `report.html`（真值图 / 宿主图 / 差异热图并排，加判据读数与应有元素表），以及每页的宿主完整日志 `<页>_host.log`。
- 全绿时现场删掉，只留一份小结 `shotgate/green/<目录名>.html`。
- 宿主截图失败（崩溃或看门狗）时，现场目录里会多一个 `KEEP` 文件，并附上系统的崩溃报告副本。
- `shotgate_gc.sh` 在每次结束时清掉超过 3 天的旧现场；带 `KEEP` 的不删，想长期保留的目录里放一个空文件 `PIN`。

| 环境变量 | 作用 |
|---|---|
| `SHOTGATE_JOBS` | 同时跑几页，缺省 6 |
| `SHOTGATE_KEEP_IMG=1` | 全绿也保留整份现场 |
| `SHOTGATE_KEEP_DAYS` | 旧现场保留天数，缺省 3 |
| `DM_GATE_SAVE` | 宿主用的存档目录，缺省 `$DM_ROOT/data/switch/save_ref_warlock/0000000000000001` |
| `DM_HOST` | 宿主可执行文件，缺省本工作树的 `dm/host/dmhost` |
| `DM_PY` | Python 解释器，缺省 `$DM_ROOT/build/cache/dm/venv/bin/python` |

## 前提

仓库里只有页规格与比对程序，下面这些要自己准备（真值从哪来见 [README.zh-CN.md](README.zh-CN.md)；取真值用的模拟器驱动脚本不随仓库提供，所以这道闸门在仓库外跑不了）：

- **真值参照图**：每页一张 `<页>.png`，旁边一份 `<页>.meta.json`。位置写在页规格的 `truth` 字段里，现有页规格指向 `$DM_ROOT/data/switch/` 下的 `truth_shots_v7`、`truth_shots_v8`、`truth_shots_v9` 三个目录（目录名写在页规格里；换存档重出参照图时另起新目录，所以带着序号）。
- **标准存档**：宿主与真值必须从同一份存档开局。`meta.json` 的 `save` 字段第一项是真值局起始存档的内容指纹（`savesha.sh` 算），宿主所用存档的指纹与它不同时，该页直接报红、不比。
- **回放文件**：站位要对齐的页（见下文）在页规格 `host.env` 里引用真值局录下的命令包文件，位于 `$DM_ROOT/data/switch/truth_runs/<局名>/`。
- **动画遮罩**：两页（`camp_e`、`wild`）引用 `$DM_ROOT/data/switch/` 下 `shotgate_masks_v2`、`shotgate_masks_v3` 里的遮罩图（同样是页规格里写的目录名）。

## 判据

`shotgate.py <页规格.json> <真值.png> <宿主.png> <报告目录>`。两张图先缩到 320×180 再比；任一条红即该页红。阈值的缺省值在 `shotgate.py` 的 `DEF` 里，页规格的 `thresholds` 可以逐页改。

| # | 判据 | 缺省阈值 | 抓什么 |
|---|---|---|---|
| ① | 结构相似度（SSIM）：灰度、7×7 盒窗，遮罩区不计 | ≥ 0.60 | 画面整体走样 |
| ② | 3D 视口里非黑像素（亮度 > 0.06）的比例 | 宿主 ≥ 真值 × 0.90 | 整块缺失 |
| ③ | 8×8 网格逐格：平均亮度差、平均颜色距离 | ≤ 0.10、≤ 0.16 | 局部缺失与偏色；红格画进热图 |
| ④ | 命名区域（角色、篝火、菜单……）：区域亮度比 宿主/真值、区域结构相似度 | 亮度比 ∈ [0.75, 1/0.75]，结构 ≥ 0.45 | 缺光照，并定位到具体区域 |
| ⑤ | 细网格（页规格有 `fine_grid` 才启用）：640×360 灰度按「列 × 行」分格，逐格平均结构相似度，只看视口内 | 页规格给下限；红格数 ≤ `fine_red_max`（缺省 0） | 一个小元素没画出来 |

另外几条：

- **应有元素表**（页规格的 `elements`）：每项指向一个命名区域，按该区域 ④ 的结论打勾；指向 `viewport` 的按 ②。写「无」的元素，意思是该位置要与真值一致（真值里本来就没有）。
- **命名区域可以单设阈值**：`{"rect": […], "ratio_min": …, "ssim_min": …}`。`ratio_min` 为 0 表示只比结构、不比亮度，给动画区用。
- **动画遮罩**（页规格的 `dynmask`）：一张遮罩图，白色是客户端自己在动的像素（火焰、旗帜等），并入遮罩不参与比较。遮罩占视口超过 30% 时，报告里标「弱判」。细网格里被遮罩盖住过半的格，结构下限改用 `thresholds.dyn_ssim_min`（缺省 0.5）。
- **宿主日志**：截图是绿的、日志里有错也判红。关键字表在 `logred.sh`（带【红】的行、FATAL、看门狗、Metal 命令缓冲错误、GPU 挂起或故障、建管线失败）。
- **`host.require_log`**：页规格列出的行必须在宿主日志里出现，缺一行即红。
- **截图前置结论**：宿主每次截图都写一行「SHOT 前置：读取画面已撤 / 本局无读取画面 / 不适用」，缺这一行即红。

为什么要有 ⑤：大区域的平均值会掩盖「一个小元素没画出来」。界面层的静态页（技能树、选项、仓库、角色属性、物品栏、任务日志等）都带细网格。

闸门跑宿主时固定设 `DM_BRIGHT_K=1`，关掉「3D 画面加亮」这个有意偏离原版的后期效果，只核画面翻译本身。

## 页规格

`shotgate_pages/<页>.json`：

| 字段 | 含义 |
|---|---|
| `page` | 页的中文名 |
| `truth` | 真值参照图路径 |
| `host.trigger` | 宿主截图时机：`<UI 消息子串>+<帧偏移>`，即该消息出现后第几帧截 |
| `host.keys` | 宿主的按键脚本（`DM_KEYS`），空串 = 不按键 |
| `host.env` | 额外传给宿主的环境变量（回放文件、种子、固定时刻、冻结拍、站位核对等） |
| `host.require_log` | 宿主日志里必须出现的行 |
| `viewport` | 3D 视口矩形 |
| `mask` | 不参与比较的矩形列表 |
| `regions` / `elements` | 命名区域与应有元素表 |
| `thresholds`、`fine_grid`、`fine_red_max`、`dynmask` | 见上节 |
| `note`、`trigger` | 说明文字，程序不读 |

矩形一律写成 `[x0, y0, x1, y1]`，取值 0–1，相对整幅画面。

`DM_KEYS` 的写法（定义在 `dm/host/hle_hid.c`）：`键@前置消息[%延时秒][+按住秒][>确认消息]`，多步用逗号隔开——等前置消息出现后按键，见到确认消息才算成功。前置消息可以写成 `DM:Tick:<拍号>#`，表示服务端走到该拍时按。

## 两边怎么停在同一个画面

要证的是：两边在「同一拍、同一服务端状态、同一客户端界面」下出同一帧。

**静态界面页**好办：真值与宿主都在同一条 UI 消息之后隔同样多帧截图。真值侧由驱动脚本按 `<触发子串>+<帧偏移>:<名>` 截，宿主侧是 `DM_NVN_SHOT_UI`，写法相同（真值按 30 帧/秒把帧数折成墙钟）。

**带 3D 场景、要走位的页**（仓库、传送点、NPC、营地、野外）难在站位：两边各自推摇杆走，停的位置对不齐，NPC 也会游荡。做法是让宿主不自己走，改为回放真值的输入：

1. **真值走位**：驱动脚本按「目标坐标 − 玩家坐标」闭环推左摇杆，走的过程中客户端发出的移动命令包与系统类消息照常录进 `c2s.jsonl`。坐标取自服务端拍入口处的玩家表（读法同 [tick_state_format.zh-CN.md](tick_state_format.zh-CN.md)）。
2. **宿主回放**：`DM_C2S_REPLAY` 回放真值的命令包到到达那一拍（下称 E 拍）。服务端逻辑逐拍等价，所以玩家、怪、NPC 的位置在 E 拍两边相同。
3. **核站位**：`DM_POSCHK=E:x:y:xf:yf` 让宿主在 E 拍入口读玩家坐标，与真值在该拍的坐标比。不同就撤掉截图，该页报「站位不一致」；相同则写一行「一致」，页规格用 `require_log` 要求这一行必须出现。
4. **开面板**：往服务端注入交互包不会让客户端开面板，所以到达之后两边都由客户端自己按键（真值发输入指令，宿主用 `DM_KEYS` 按拍号按），并以 UI 消息确认面板已开。
5. **冻结拍截图**：画面随拍变化的页，两边都停在同一拍再截。宿主 `DM_TICK_HOLD=E:SHOT` 在进入 E 拍时冻结游戏时钟，截图写盘后解冻，触发写成 `DM:Tick:E#+N`；真值侧在 E 拍开始后的第一帧截图。这样截到哪一拍与帧率、本机负载无关。

客户端自己在动的东西（火焰、环境小动物）不在服务端状态里，冻结拍也对不齐，靠动画遮罩或放宽个别区域的阈值处理。遮罩的做法：真值侧在同一冻结拍连截两张，再用 `dynmask.py <a.png> <b.png> <输出遮罩.png> [阈值=8] [膨胀像素=3]` 取两张之差。

## 怎么出真值参照图

真值参照图由真值模拟器出，仓库里不带；出图用的模拟器驱动脚本也不随仓库提供。

- 静态界面页在触发消息之后隔若干帧截；要走位的页在到达拍截（见上节）。每页一张 `.png` 加一份 `.meta.json`。
- 出好的图连同 `meta.json` 放进页规格 `truth` 字段指的目录。换了标准存档就要重出全部参照图，放进新目录并改页规格，不覆盖旧目录。

## 加一页

1. 在真值侧定下触发消息与帧偏移（或到达拍），出参照图。
2. 写 `shotgate_pages/<页>.json`：照参照图框出视口、命名区域与应有元素；界面层静态页加 `fine_grid`。
3. 做负对照：把参照图里某个元素抹掉再比，闸门必须报红。判据抓不到的缺失，说明区域或阈值没设对。
