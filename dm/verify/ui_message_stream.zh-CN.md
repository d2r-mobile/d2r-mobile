# UI 消息流格式

English: [ui_message_stream.md](ui_message_stream.md)

游戏界面的每一次变化（开面板、关面板、切页、移动光标……）都由游戏自己发一条 UI 消息。把一局里的 UI 消息按先后记成一个文件，就能比较两边的界面流程是否一致：一边是**真值**（用打了补丁的 Ryujinx 模拟器跑原版游戏得到的参照数据），一边是**宿主**（`dm/host` 的 `dmhost`，在 Mac 上执行改写后的游戏程序）。本页定义这个文件的格式与对照规则。

## 采集点

- 游戏所有 UI 消息都经 UI 总线对象 `*(main + 0x2f05458)` 的虚函数 `+0x28` 投递；在 3.3.94012 的 `main` 里，实现函数是 `main + 0xb1dc60`（以运行时读虚表为准，不写死）。
- 入口处：`x0` = 总线对象，`x1` → 消息头 `{+0x00 u64 类别哈希, +0x08 u64 动作哈希, +0x10 u64 载荷指针}`。
- 哈希是 FNV-1a 64（偏移基 `0xcbf29ce484222325`，乘数 `0x100000001b3`），对原字串逐字节算。例：`PanelManager` = `0x7127a406e0b6452c`。
- 同一虚函数偶有非消息调用（`x1` 不是可读指针）：不输出。

## 每条一行 JSON

UTF-8，`\n` 结尾，字段顺序固定：

```
{"seq":N,"cat_h":"0x7127a406e0b6452c","act_h":"0x...","arg":"MainMenuPanel","cat":"PanelManager","act":"OpenExclusivePanel"}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| seq | 是 | 本局第几条（从 0 起，只数输出的消息） |
| cat_h / act_h | 是 | 类别 / 动作哈希，`0x` + 16 位小写十六进制。**对照只用这两个与 arg** |
| arg | 是 | 载荷指针指向的 C 串（≤ 64 字节，以 0 截断；须全为可打印 ASCII 或 UTF-8 高位字节），否则 `null` |
| cat / act | 否 | 名字，只供人读：用 `main` 只读区 `[0x1b79000, 0x2056000)` 里全部 ≥ 3 字节可打印串的 FNV-1a 反查；查不到就省略 |

- 不输出时间、帧号、线程号、指针值：这些两边不可比。
- 文件位置：真值侧是 `<局目录>/uimsg.jsonl`（模拟器驱动脚本写；这些脚本不随仓库提供，所以依赖真值的检查在仓库外跑不了）；宿主侧用环境变量 `DM_UIMSG=<路径>` 指定，缺省不记。

## 对照规则

由 `dm/verify/uicmp.py` 实现：`uicmp.py <真值 uimsg.jsonl> <宿主 uimsg.jsonl> [--until <arg>]`，退出码 0 = 一致。

1. 两边各自按 `(cat_h, act_h, arg)` 取序列。
2. 先剔除豁免表里的消息（见下），再把**相邻完全相同的消息折叠为一条**：只比是否出现，不比条数。
3. 折叠后逐条相同即一致；否则报第一处不同的位置，以及两边该位置前后各 3 条。
4. 同时报射程（这次比较实际覆盖了多少）：折叠前 / 后条数、不同类别数。

`--until <arg>`：两边都截到第一次出现该载荷（含）为止，只比同一段流程。

## 豁免表

豁免登记在 `uicmp.py` 的 `EXEMPT` 里；每加一条都要在这里写明理由。

| 动作 | 载荷 | 理由 |
|---|---|---|
| OpenPanel / ClosePanel | SaveIndicatorPanel | 时序竞态。`0x2442ac` 把「存档中」标志置 1 再清 0，间隔不到 1 毫秒；只有恰好有一帧落在这个窗口里，`0xb14e00` 才开始显示存档指示，随后 `0xad42d4` 按墙钟的最短时长保持显示，期间每帧重发 OpenPanel。出不出现取决于帧率与运气，两边不可比。`LoadPanel SaveIndicatorPanel` 不在豁免之列，照常对照 |

跑法要求：存档副本一律可写。只读副本会让写存档那一步不发生，偏离真机。

## 光标载荷（驱动用，不进对照）

`InputMessage:MouseMove` 的载荷指针指向的 `+4` / `+8` 是两个 `u32` 光标坐标。驱动脚本读出它们，真值局的 `events.jsonl` 里这条 UI 事件会多一个 `cursor: [x, y]`；`uimsg.jsonl` 仍只有上面六个字段，对照口径不变。

驱动脚本的计划（真值局按游戏数据推进的动作序列）可以拿光标当确认条件：

- `press <键> cursor:x:y:r released`：发键后要见到新的光标消息落在目标半径 `r` 内，并且最后一条 `ControllerActionBegin/End` 是 End，才进入下一步。
- `assert cursor:x:y:r`：只核当前光标位置，不要求再移动。

光标坐标随窗口尺寸与所在页面而变，某一页量到的坐标不能外推到别的页面。
