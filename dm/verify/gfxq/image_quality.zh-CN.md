# 画质度量

English: [image_quality.md](image_quality.md)

这个目录里是两把量画面的尺子，都在 Mac 上用宿主（`dm/host` 的 `dmhost`）离线截图来量：

- **G1**（`shoot.sh` + `g1.py`）：某个内部分辨率下的画面，离「这块手机屏幕上能达到的最好画面」有多远。用来选内部分辨率。
- **视觉等价尺子**（`ruler.sh`）：打开某项渲染优化之后，画面是否与不开时等价。用来给图形层的优化把关。

两者都用 NVIDIA FLIP 度量两张图的差异。FLIP 是一种模拟人眼观看的图像差异指标，0 = 看不出差别；源码在 `dm/third_party/flip/`（BSD-3），先 `make -C dm/third_party/flip` 编出 `dm/third_party/flip/flip`。

## G1：离原生分辨率有多远

### 口径

- **参照帧**：同一冻结帧，按屏幕原生分辨率 2868x1320 画出，不经放大。
- **被测帧**：同一帧按某个内部分辨率（`DM_GAME_RES`）画，再经真实的出图路径（图形层的 `present_encode`）放大到 2868x1320。截图尺寸由 `DM_NVN_SHOT_OUT=2868x1320` 固定，`shoot.sh` 已经带上。
- **Switch 基线**：900 高、双线性放大。宽度按屏幕比例取 1952（1952x900），不用 16:9 的 1600x900——16:9 出图会居中加黑边、界面布局也不同，没法与参照帧逐像素对上。
- **G1** = FLIP（LDR）均值，`-ppd 95`，对全部帧取平均。`ppd` 是每度视角的像素数：iPhone 17 Pro Max 约 460 ppi、观看距离 30 cm，0.30 × tan 1° ÷ 0.0254 × 460 ≈ 95。
- **目标**：手机方案的 G1 ≤ Switch 基线 G1 的一半。

量的是清晰度：内部分辨率只改清晰度，不改视野与布局。

### 帧清单

`frames.tsv` 列了 20 帧，每行「编号、名字、来源」：

- 01–16 直接取[画面闸门](../screenshot_gate.zh-CN.md)页规格（`shotgate_pages/*.json`）里的触发、键序与环境变量。
- 17–20 是四个战斗帧：回放一份真值局录下的命令包（真值 = 用打了补丁的 Ryujinx 模拟器跑原版游戏得到的参照数据），用 `DM_TICK_HOLD=<拍>:SHOT` 停在指定的拍截图。

前提：

- 标准存档 `$DM_ROOT/data/switch/save_ref_warlock/0000000000000001`（`DM_GATE_SAVE` 可换）。
- 页规格里引用的真值回放文件；战斗帧的回放文件路径写死在 `shoot.sh` 与 `ruler.sh` 里，指向 `$DM_ROOT/run/verify/ryu/` 下的一个真值局目录。这些仓库里没有；录制用的模拟器驱动脚本也不随仓库提供，所以用到真值回放的帧在仓库外跑不了，见 [../README.zh-CN.md](../README.zh-CN.md)。

### 命令

```
make -C dm/third_party/flip
bash dm/verify/gfxq/shoot.sh dm/host/dmhost <产物目录> <宽x高> <输出目录> [并行数=4] [编号或名字…]
python3 dm/verify/gfxq/g1.py <参照目录> <被测目录> [--flip <flip 路径>]
```

- `shoot.sh` 每帧起一个宿主，输出 `<输出目录>/<编号>.png` 与 `<编号>.log`；不给编号就跑全部 20 帧。有帧失败时列出失败帧，退出码 1。
- `g1.py` 比两个目录里同名的 PNG：逐帧打印 FLIP 均值，末行给出 G1 均值与最差的 3 帧。被测目录缺帧或两边尺寸不同时报红，退出码 1。`--flip` 缺省就是 `dm/third_party/flip/flip`。

一次完整的量法：先用 `2868x1320` 出参照目录，再用各个候选分辨率各出一个被测目录，分别与参照目录算 G1。

### 关于显存预算

游戏自己的显存分配器有一个预算常数（`main + 0x8524c4`），原版是 260 MB。这个预算下内部分辨率一高，渲染目标就放不下、游戏启动即崩，画不出原生分辨率的参照帧。

改写器已经把这个常数登记为剪口（`dm/tools/patch_nso.py` 的 `CUTS`），所有产物里都是 512 MB，所以参照帧直接用普通产物出即可。`truth_out.sh` 是这条剪口进改写器之前的做法：把一份仍是 260 MB 的产物复制成 `<源>-truth` 并改这一条指令。它会先核对源产物该处是不是原来的指令，对现行产物会报红退出，不需要再用。

### 规矩

- **参照帧与被测帧必须用同一个宿主二进制出。** 宿主的回放节拍一变，两个二进制画的就不是同一刻，差出来的是系统偏差而不是画质变化。所以每次出读数都先用当前宿主重出参照帧，再出被测帧。
- **跑帧用产品节奏，不设 `DM_DETCLOCK`。**（`DM_DETCLOCK` 是给逻辑类测试用的确定性时钟。）设了它，游戏拍会跑在异步加载与界面前面，面板与读取画面的行为既不像产品也不确定。
- **噪声底每次实测。** 冻结帧做不到逐字节可复现：火焰、动画这类客户端自己在动的东西，两次运行不会停在同一刻。同一个二进制、同一个配置跑两遍，两遍之间的 FLIP 就是噪声底（逐帧与均值都记）；超过噪声底 2 倍才算差异。噪声底不沿用旧数。
- **原生档的宽必须恰好等于屏幕宽。** 只差几列，出图也要整屏重采样，每个像素都被插值一遍。

## 视觉等价尺子：`ruler.sh`

G1 要跨运行比，噪声底偏高，量不出小差异。判断「开了某项优化之后画面还是不是同一张」用这把尺子：它在**同一个进程、同一冻结拍**里连截三张。

```
bash dm/verify/gfxq/ruler.sh <dmhost> <产物目录> <宽x高> <输出目录> [帧号…]
```

- 每帧起一个宿主。`DM_NVN_RULER=1` 让宿主先用「参照设置」（图形层针对苹果显卡做的那批渲染优化全部关掉）截 A、B 两张，然后切到被测设置（缺省全开，加上调用方透传的环境变量）截 C。三张各隔 8 帧。
- **噪声** = FLIP(A, B)，**差异** = FLIP(B, C)，都用 `-ppd 95`。
- 不给帧号时跑 4 帧：`02` 营地、`16` 野外、`18` 战斗、`06` 物品栏。
- 输出 `<输出目录>/<帧号>_{A,B,C}.png` 与 `<帧号>.log`；每帧打一行读数与判定，末行「汇总：n/m 帧等价」；有不等价的帧则退出码 1。

判定分两种口径，用环境变量 `RULER_MODE` 选：

| 口径 | 适用 | 判等价的条件 |
|---|---|---|
| `exact`（缺省） | 合并、跳过这类应当出同一张图的优化 | FLIP 差异 ≤ 0.01 且 ≤ 2 × 噪声 + 0.002；并且「大差像素」（任一通道差 > 30/255）的个数：B–C ≤ 2 × A–B + 画面像素的 0.005% |
| `approx` | 降分辨率、换滤波这类近似 | FLIP 差异 ≤ 0.02；并且差 > 60/255 的像素数：B–C ≤ 2 × A–B + 画面像素的 0.05% |

为什么要数大差像素：FLIP 均值对局部缺损不敏感，一小块没画出来，均值几乎不动。

负对照：`DM_NVN_RULER_NEG=<片元着色器键>` 让被测设置丢掉用该着色器的绘制，尺子必须报不等价。新加判据或改了切换时机之后，先跑一次负对照，确认尺子没有空转。

限制：这把尺子只能量运行中可以切换的设置。
