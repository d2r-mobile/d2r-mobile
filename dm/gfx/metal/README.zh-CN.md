# dm/gfx/metal — 最小 Metal 离屏示例

English: [README.md](README.md)

一个独立的小模块：用纯 C 接口包住 Metal，把画面渲到离屏纹理再读回 CPU，不上屏。它不编进宿主（`dm/host/Makefile` 不收本目录），游戏实际用的 Metal 回放层在 `../nvn/nvn_mtl.m`。这里留作一个能独立编译、几十行就能看懂的参照，以及验证 Metal 行为的小探针。

## 接口（`mtl_backend.h`）

| 接口 | 作用 |
|---|---|
| `mtlb_init()` / `mtlb_shutdown(ctx)` | 建 / 释放上下文：设备、命令队列、当前帧的命令缓冲、管线缓存 |
| `mtlb_target(ctx, w, h, fmt)` / `mtlb_target_free(rt)` | 建 / 释放一个离屏渲染目标，格式为 `MTLB_FMT_BGRA8` 或 `MTLB_FMT_RGBA8` |
| `mtlb_clear(ctx, rt, r, g, b, a)` | 往当前帧录一个渲染通道，把目标清成指定颜色 |
| `mtlb_triangle(ctx, rt)` | 往当前帧再录一个渲染通道（保留已有内容），画一个三色三角形 |
| `mtlb_readback(ctx, rt, buf, size)` | 提交当前帧、等 GPU 完成，把像素按行紧排读回 `buf`（第 0 行是图像顶部） |

函数返回 0 表示成功、-1 表示失败，失败原因打到标准错误。实现在 `mtl_backend.m`（Objective-C，ARC）。

设计要点：

- **一帧一个命令缓冲**：第一次录通道时才创建，之后的清除、三角形都追加进同一个命令缓冲，读回时才提交。
- **渲染目标不是全局变量**：上下文与每个目标都是不透明指针。
- **存储模式用 Shared**：在统一内存设备上，Shared 纹理可以直接当渲染附件，GPU 完成后 CPU 直接读，不需要中转缓冲。非统一内存设备上 `mtlb_init` 直接报错。
- 三角形的着色器是内联的 MSL，运行时编译。

## 编译与运行

```sh
make -C dm/gfx/metal        # 产出 test_offscreen
make -C dm/gfx/metal run    # 跑自测，退出码 0 表示全过
make -C dm/gfx/metal clean
```

只需要 Xcode 的命令行工具，不需要游戏文件。编译产物已列入本目录的 `.gitignore`。

## 自测（`test_offscreen.c`）

期望值全部在测试里独立算出，不读后端内部数据：

- 三角形顶点在测试里另抄一份；
- 归一化坐标换算到像素：`px = (x + 1) / 2 · W`，`py = (1 − y) / 2 · H`；
- 像素中心的颜色按重心坐标对三个顶点颜色线性插值。

两个测试对 BGRA8、RGBA8 两种格式各跑一遍：

1. 清成纯色，逐像素比。
2. 清屏后画三角形：三角形内侧（离边超过 1 像素）的像素与插值值比，容差见源码里的 `TOL`；外侧像素与清屏色比；紧贴边的 1 像素带跳过，光栅化的边缘规则不在本测试范围内。

读回前先把缓冲填成 0x5a，防止「后端什么都没写也判过」。

## 探针（`probe/p_nocopy.m`）

单文件程序，没有构建目标，需要时手动用 clang 编译。它验证回放层内存池做法所依赖的一件事：在一段不按页对齐的内存上，把首尾外扩到页边界后可以建成零拷贝的 `MTLBuffer`，两个这样的缓冲允许重叠，GPU 写入的内容 CPU 经原指针能读到。

## 局限

- 三角形顶点写死在 `mtl_backend.m`，没有顶点缓冲、着色器、视口等可配置状态。
- `mtlb_readback` 同步等整帧完成，会阻塞调用线程。
- 只支持单个颜色附件、两种 8 位格式；没有深度 / 模板、多重采样、多附件。
- 非线程安全；只支持统一内存设备。
