# uireg — 触摸界面的脚本化回归

English: [usage.md](usage.md)

把触摸界面逐项点一遍，每项出一行「期望 → 真结果」。被测的是 iOS 包本身，只用触点脚本驱动（和真手指走同一条路，见 [../../README.zh-CN.md](../../README.zh-CN.md)「触点脚本」），判据读这一局的日志。

**先说存档**：整套回归是照着一份特定的多角色存档写的，这份存档不随仓库提供，也不能分发。仓库里能生成的冒烟存档只够跑冒烟。详见下面「需要什么存档」；没有那份存档时，多数局的现场和点位对不上。

## 文件

| 文件 | 作用 |
|---|---|
| `uireg.py` | 全部用例与判据：生成每一局的触点脚本、调起局脚本、读日志出结果表 |
| `run_mac.sh` | 起局脚本（缺省）：在本机跑 Mac 上的 iOS 包 |
| `run_dev.sh` | 起局脚本：在真机 iPhone 上跑已装好的包 |
| `uireg_pick.py`、`affected.tsv` | 按改动的文件挑出受影响的局 |

## 前提

1. 能在 Mac 上跑 iOS 包：先按 [../../README.zh-CN.md](../../README.zh-CN.md)「冒烟」跑通一次 `tools/make_fixture.sh` 和 `tools/smoke_mac.sh 1`。这之后本机就有包好的包（仓库根目录下 `.iosdd_mac/DmMacSmoke.app`；源码不是用 git 克隆来的话，它在你运行冒烟脚本时所在的目录下）、这个 App 的容器，以及容器里的游戏资源。
2. 本机配置 `dm/ios/local.env` 里有 `DM_BUNDLE_ID`。
3. 部分判据要读截图，需要 `python3` 能 `import PIL`（Pillow）。没有也能跑，这些项会报「未判」。

全部步骤都可以只在本机做，不需要第二台 Mac。

## 跑法

```bash
# 在仓库根目录执行
python3 dm/ios/tools/uireg/uireg.py iphone            # 全部局
python3 dm/ios/tools/uireg/uireg.py iphone b          # 只跑 b 局
python3 dm/ios/tools/uireg/uireg.py iphone a c e      # 跑几局
```

第一个参数是画面档：

| 画面档 | 含义 | 用哪个包 |
|---|---|---|
| `iphone` | iPhone 比例 | `UIREG_APP`，缺省是仓库根目录下的 `.iosdd_mac/DmMacSmoke.app`（源码不是用 git 克隆来的话没有缺省值，要自己给） |
| `ipadfull` | iPad 真全屏（iPad 上的缺省画面：3D 铺满整屏，界面是贴底的一块 16:9） | `UIREG_APP_IPAD`，必须给 |
| `ipad` | iPad 16:9 留边 | 同上 |

一局 = 启动一次 App、走一段脚本、退出。各局互相独立，可以单独跑。局与局之间串行：同一个包名在一台 Mac 上只能有一个实例，起局脚本用 `$DM_ROOT/run/ios/macsmoke.lock` 这把锁和 Mac 冒烟排队。

### 结果怎么看

- 每跑完一局打印一行：墙钟时间、计时分段、日志里的红行数。
- 最后一行：`# 共 N 项：通 A、不通 B、未判 C；合计墙钟 … 秒；表 <路径>`，后面跟着每个没通过或未判的项。
- 结果表：`$UIREG_OUT/tables/<画面档>_<月日_时分>/表.md`。
- 每局的现场：`$UIREG_OUT/pw/<前缀>_<画面档>_<局名>/`，里面有 `boot.txt`（这一局的日志）、`script.txt`（实际用的触点脚本）、截图、`timing.txt`。

「未判」有两种：这一项只留了截图、没有日志判据；或者判据要读截图但读不出来。两种都要人看图才能下结论，不会被当成通过。

每一项的判据只看日志里该项记号之后的那一段。红行的口径不只是带「【红】」的行，还包括 `FATAL`、看门狗、GPU 命令缓冲出错等，正则在 `uireg.py` 的 `LOGRED`。

## 需要什么存档

### 标准存档

多数局启动时带 `DM_SAVE_FRESH=warlock`：App 把自带的标准存档拷一份新的来用，不碰真实存档。标准存档是出包时从 `$DM_ROOT/data/switch/save_ref_warlock/0000000000000001/0/` 带进 App 的。

脚本假定这份存档的选角列表里有四个角色，并且各局按行号去选：

| 行 | 脚本假定的角色 | 用到它的局举例 |
|---|---|---|
| 1 | 76 级圣骑士 | `i`、`me1`、`me2`、`sl1`、`rf1` |
| 2 | 1 级术士（缺省选这一行） | 大多数局 |
| 3 | 另一个角色 | `e`（只在选角页选中它）、`wd1` |
| 4 | 88 级法师，带佣兵 | `f`、`q`、`tp`、`cb`、`pg1`、`bdm`、`rf2`、`me3` |

许多点位和判据还依赖这些角色身上现成的东西（背包里的卷轴、身上的装备、仓库内容、已开的小站）。

**这份四角色存档不在仓库里，需要自备。** `tools/make_fixture.sh` 生成的冒烟存档只有两个新建的角色，放在同一个目录；用它跑回归，哪些局能过没有验证过。要跑整套，得自己准备一份满足上表的存档放到那个目录，再重新出包。

各局需要的物品、金币、站位不靠存档，由测试开关在进局后当场给出（`DM_TEST_GIVE` 等，写在 `uireg.py` 每一局的定义里），并固定了随机种子与游戏时间，所以同一份存档每次跑出来的现场相同。

### 专用存档

下面几局不用标准存档，而是换上一份专用存档。它们同样不在仓库里，要自备；目录名是脚本里写死的，名字本身没有含义：

| 目录名 | 用它的局 | 脚本假定的内容 |
|---|---|---|
| `save.pw_rune_stack`（可用 `UIREG_STACK_SAVE` 改名） | `d`、`t`、`u` | 术士；箱子的符文页里有一叠 12 个符文 |
| `save.rg_act4done` | `g1`–`g4` | 第四幕已通关的角色 |
| `save.rg_act4` | `ex` | 在第四幕、小站已开的角色 |
| `save.rg_joejoe` | `tb`、`dz` | 在第二幕的角色，脚本从城里的小站去法师峡谷；`dz` 还要背包里带着任务法杖 |
| `save.sl_player` | `vf1` | 个人仓库与共享仓库里都有物品的角色 |

放法：把存档目录放到 Mac 上这个 App 容器的 `Data` 目录下（和 `Documents` 同级），目录要可写。`run_mac.sh` 在这一局开始前把容器里现有的 `Documents/save` 挪开，换上专用存档的副本，跑完再挪回；万一挪不回会报红并写明原存档在哪。

没有对应目录时，这一局直接失败并在 `fail.txt` 里写明缺哪份存档，不影响别的局。

## 有哪些局

局名是 `uireg.py` 里 `G("…")` 的第一个参数，下面按内容分组。具体每一项点什么、判什么，以 `uireg.py` 里该局的定义为准。

| 局 | 内容 |
|---|---|
| `e` | 选角页、建角、起名（会新建一个角色并进局） |
| `v` | 勾选建角页上的附加模式后建角，进局开箱看共享页 |
| `a` | 装备位换装、底栏与面板页签、小地图、摇杆、野外技能施放、暂停菜单与设置页 |
| `b` | NPC 对话菜单、商人页买卖、物品栏的单击 / 拖放 / 双击 / 长按 |
| `c` | 储藏箱拖放与页签、金币数量框、几种弹框开着时点框外 |
| `s`、`sb` | 符文放进储藏箱再取出；储藏箱每个按钮逐个点 |
| `d`、`t`、`u` | 从成叠的格子里取件：基本手法、背包里带着魔盒时、背包只剩一格时（专用存档） |
| `g`、`h` | 技能绑定；技能树的「综合技能」页 |
| `i`、`f`、`q`、`bdm` | 雇佣兵：雇佣与复活、带佣兵时物品栏拖放、双击腰带药水喂佣兵 |
| `j`、`k` | 镶嵌；做一个符文之语 |
| `rw1`、`rw2`、`rwp`、`rwd` | 符文之语清单：长按打开、分页与详情、一键合成 |
| `m`、`n`、`p`、`ra` | 商人页：拖到商人面板卖出、货架长按大量购买、长按药水补腰带、全部修理 |
| `me1`–`me4` | 不同角色面对同一个 NPC 时两行 / 三行 / 四行的对话菜单 |
| `sl1`、`sl2`、`sl3` | 灌魔、打孔、个性化。`sl2`、`sl3` 在脚本注释里标明是还没实际跑过的草稿 |
| `cb` | 魔盒页开着时双击把物品送进 / 送出魔盒 |
| `bd`、`ba` | 腰带：空格双击补满、开背包自动补腰带 |
| `pk`、`g1`–`g4`、`ex`、`tb`、`tp`、`dz` | 点世界里的东西：箱子的可点范围、传送门上中下几段、出口、回城门、任务底座（多数要专用存档） |
| `wp` | 进局落在城镇小站旁 |
| `rf1`–`rf3` | 暂停菜单的一键重开，每局连开三次 |
| `pg1`、`pg2` | 个人仓库翻页 |
| `vt1`、`vf1`、`vf2` | 储藏箱的第六个页签（外壳加的收藏页）：存入、取出、搜索、页签来回切 |
| `kba`、`kbb` | 击杀统计面板：各控件逐个点；击杀之后看统计 |
| `wd1`、`wd2` | 无进展看门狗：回到前端静置不误判；启动后一直不动仍会判定 |
| `dc` | 野外死亡 → 点死亡画面的「继续」→ 复活回城 |
| `top` | 只在 `ipadfull` 档存在：屏幕真顶部的小地图与地名、各面板标题栏 |

不写局名时的范围：

- `iphone`、`ipadfull`：上表全部（`top` 只在 `ipadfull`）。
- `ipad`（留边档不是 iPad 的缺省画面）：只跑和画面比例有关的那部分，自动跳过 `d g h j k t u v m n p ra q pk g1–g4 ex tb tp`，`a` 局里跳过野外施放那一段。点名仍然可以跑。
- `g1`–`g4` 的点位只量了 `iphone` 和 `ipadfull` 两套。

## 环境变量

| 变量 | 含义 | 缺省 |
|---|---|---|
| `UIREG_RUNNER` | 起局脚本 | 同目录 `run_mac.sh` |
| `UIREG_OUT` | 产物根目录 | `$DM_ROOT/run/uireg` |
| `UIREG_APP` | `iphone` 档的包（`<名>.app`，里面是 `Wrapper/DmIOS.app`） | 仓库根目录下 `.iosdd_mac/DmMacSmoke.app` |
| `UIREG_APP_IPAD` | `ipad` / `ipadfull` 档的包 | 无，必须给 |
| `UIREG_STACK_SAVE` | `d`、`t`、`u` 局专用存档的目录名 | `save.pw_rune_stack` |
| `UIREG_EXTRA_ENV` | 每局都加给 App 的环境变量（空格分隔的 `K=V`） | 不设 |
| `UIREG_FORBID` | 正则：整局日志里出现就算不通 | 不设 |
| `UIREG_REQUIRE` | 正则：整局日志里必须出现，结果里写出现次数（用来确认某个开关真的生效了） | 不设 |
| `UIREG_TAG` | 每局现场目录名的前缀（两遍回归先后排队时分开放） | `ur` |
| `SMOKE_OWNER` | 排锁时显示的名字 | 未署名 |

## iPad 档的包

仓库里没有单独出 iPad 包的脚本。做法和 `tools/smoke_mac.sh` 里出包的那两步相同，只多一项构建设置：

1. 同样的 `xcodebuild` 命令，把其中的 `DM_DEVICE_FAMILY=1` 换成 `DM_DEVICE_FAMILY=1,2`（设备族里加上 iPad；`tools/smoke_mac.sh` 出包时固定只面向 iPhone，不跟 `../../project.yml` 的缺省值走）。
2. 同样包成 `<名>.app/Wrapper/DmIOS.app`，外加 `WrappedBundle` 软链。

每次出包用一个新的目录名，然后把路径给 `UIREG_APP_IPAD`。

## 换包的规矩

Mac 跑 iOS 包时，系统把 `<包>/Wrapper` 挂载出去运行。挂着的时候这层目录被删或被整体替换，会留下卸不掉的失效挂载点，那个路径从此打不开，只有重启能清。所以：

- 包在跑的时候不动它。
- 要换包就换一个目录名；或者只做同名文件的增量更新，不删、不整体替换 `Wrapper`。

`run_mac.sh` 自己不拷包，直接从给的路径启动。

## 在真机上跑

```bash
UIREG_RUNNER=dm/ios/tools/uireg/run_dev.sh python3 dm/ios/tools/uireg/uireg.py iphone a c
```

`run_dev.sh` 通过 `../touch_e2e.sh` 在手机上跑**已经装好的那个包**，前提与真机冒烟相同（见 [../../README.zh-CN.md](../../README.zh-CN.md)「真机冒烟」）。和 Mac 上的差别：

- 只有 `iphone` 档。
- 要专用存档的局不跑。
- 每局跑满上限秒才收；日志截到脚本结束的记号为止，全文另存为 `boot_full.txt`。
- 缺省只拉回日志，不拉截图，所以要看截图的项在真机上都是「未判」。要拉某几张截图，用 `UIREG_PULL="<文件名> <文件名>"` 点名。
- 它不负责装包。要保证被测的是自己刚装的包，在外层先取设备锁，把「装包 + 跑」包在一起（设备锁可重入，`../devlock.sh`）。

## 按改动挑局

```bash
python3 dm/ios/tools/uireg/uireg_pick.py <被测提交或分支> --main <主干分支>
```

它比较被测提交与主干的分叉点之后改了哪些文件，按 `affected.tsv`（路径通配 → 受影响的局）列出该跑哪些局，最后一行 `局：…` 就是要跑的局名。`*` 表示要跑整表；没有登记的 `dm/` 下的源文件按整表处理。加 `--core`，或者没有任何受影响的局时，会并上脚本里的一组核心局。新加一局时记得在 `affected.tsv` 里登记。

## 挂在 Mac 冒烟后面的那一局

`tools/smoke_mac.sh` 带 `SMOKE_UIREG=1` 时，冒烟通过后会加跑一遍 `iphone b`：

- 放在后台跑，不影响冒烟自己的结果和退出码。
- 用的是这次冒烟的包的一份克隆副本，所以紧接着再冒烟、重新包装都碰不到它正开着的那份。
- 跑完往冒烟记录 `$DM_ROOT/run/ios/smoke_ledger.tsv` 补一行，结果列是 `Mac:界面回归b:OK` 或 `Mac:界面回归b:RED`。通过的条件：有判据的项全通，且日志红行为 0；「未判」不计。
- 红了，现场留在那次冒烟结果目录的 `uireg/` 下，下一次冒烟开头会提示一句。

注意 `b` 局同样依赖上面说的标准存档。

## 自己写起局脚本时的约定

想让同一套用例跑在别的环境上，可以另写一个起局脚本，用 `UIREG_RUNNER` 指过去：

- 调用方式：`bash $UIREG_RUNNER <标签> <上限秒>`，触点脚本从标准输入给。
- 传入的环境变量：`PW_ENV`（空格分隔的 `K=V`，原样加到 App 的启动环境）、`PW_SAVE`（要换上的专用存档目录名，多数局为空）、`UIREG_MODE`（画面档，据此挑包）、`UIREG_OUT`。
- 产物放到 `$UIREG_OUT/pw/<标签>/`：`boot.txt`（必需）、截图（用脚本里 `shot` 给的原名）、`timing.txt`（一行以「计时：」开头的文字，会原样抄进结果表）、`c2s.jsonl`（游戏发出的命令包记录，可以没有）。
- 触点脚本的最后一行是 `<秒> note 结束`：日志里出现 `[script] note 结束` 就可以收，上限秒只是兜底。
